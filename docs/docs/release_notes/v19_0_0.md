# CodeLite 19.0.0 Release Notes

This release covers all changes since **18.5.0**. It is a work in progress — this page will be updated as new commits land.

## Improvements

- The *Web development* profile of the bootstrap wizard no longer enables the removed `WebTools` plugin.
- The **Claude Code** plugin is now called **Agent Host**, and its menu moved to `Plugins` → `Agent Host`. Your existing settings (including the path to the `claude` executable) are kept, and the plugin stays enabled after you upgrade.
- The keyboard shortcut for `Launch Claude Code` changed from `Ctrl-Shift-I` to `Ctrl-Shift-C`.
- The keyboard shortcut for the Diff plugin's `New File Comparison` changed from `Ctrl-Shift-C` to `Ctrl-Alt-C`, to avoid clashing with the new Agent Host shortcut.
- Double-clicking in the built-in terminal now selects a whole URL or command that contains `=` or `?`, instead of stopping at those characters.
- The tab switcher (`Ctrl-Tab`) now uses the same alternate row colours as the rest of the IDE.
- Opening a file that can't be read, or one larger than 100 MiB, is now logged as a debug/warning message instead of an error, which reduces noise in the log.
- Loading a remote workspace is now faster. The SSH connection for the remote language server (LSP) is created in the background, so the UI no longer waits for it. In tests, loading is 3x faster or more.
- **Agent Host** now supports **Kiro CLI**. Each agent type keeps its own page.
- **Agent Host** now supports **OpenCode**.
- **Agent Host**: the side bar now has one button (instead of one button per agent), and the menu has one item, `Launch an AI Agent...` (`Ctrl-Shift-C`). Both open a dialog that suggests an agent: the last one you used, or the first one that is installed. Choose `Claude Code`, `Kiro CLI` or `OpenCode` and start it. The shortcuts of the single agents (including `Ctrl-Shift-K` for Kiro CLI) are removed.
- **Agent Host**: the `Settings` dialog now has the path to the `kiro-cli` and `opencode` executables (like the one for `claude`), and the extra review arguments for OpenCode. If a path is empty, CodeLite looks for the executable in the `PATH`.
- Starting a build now moves the focus to the `Build` tab of the Output pane.
- A terminal that you open with a keyboard shortcut now starts in the working folder of the active workspace.
- Agent Host now moves the focus to the terminal when you click its tab. The warning about a missing workspace now shows the name of the agent.
- The tab of a read-only editor now shows a lock icon.
- The tooltips of the side bar buttons now show the keyboard shortcut of the action.
- Double-clicking in the built-in terminal now keeps `@` and `&` inside the selected word.
- The `Save` toolbar button and menu item are now enabled only when the editor has unsaved changes.
- The right-click menu of a tab that is not an editor now shows only the close actions (`Close`, `Close All`, `Close Other Tabs`, `Close Tabs To The Right`). The `More Copy Options` submenu is hidden for these tabs.
- The tab bar drawing on macOS now shares the code used on the other platforms, and tab borders use one colour.
- On Linux (GTK), CodeLite no longer shows a dialog and starts `gdb` when it crashes with `SIGSEGV` or `SIGABRT`. It now crashes normally.
- On Linux, a crash (including `SIGABRT`) now prints a stack trace before CodeLite exits.
- Saving a remote file over SFTP is faster: it needs fewer network round trips (5 instead of 7 for an existing file, 4 for a new file). This also makes loading a remote workspace faster on slow connections.
- Creating a remote folder over SFTP now works like `mkdir -p`: missing parent folders are created too.
- **wxCrafter**: added a `Generate .h files` option. When it is enabled, generated derived-class headers use the `.h` extension instead of `.hpp`.
- On Linux under WSLg, icons are now scaled by `GDK_DPI_SCALE` (between 1 and 2), so they match the size of the other controls.
- **SFTP**: added `Sync Folder with Remote` to the right-click menu of folders in the folder views. Choose the account and the remote folder, select the files, and CodeLite uploads them one by one. When the sync starts, the `SFTP Log` view opens and shows the progress, and you can cancel there. See the [SFTP plugin](../plugins/sftp.md#sync-folder-with-remote) page.
    - The file list has a filter field (not case sensitive, matches any part of the name), `Select All` and `Unselect All` buttons, and the ++space++ key checks or unchecks the selected file.
    - CodeLite remembers the account and the remote folder, and the missing remote folders are created for you.
    - In a File System Workspace with `Enable remote development`, the dialog is filled with the account and the remote folder of the workspace: `<remote workspace folder>/<selected folder, relative to the workspace root>`. If remote development is disabled, or no remote folder is set, the `Remote folder` field is empty.
- **SFTP**: added `Sync Files with Remote` to the right-click menu of files in the file views. Select one or more files (they can be in different folders) and upload them to the remote machine. The file list shows the `Local Path` and the `Remote Path` of each file, relative to the `Local Folder` and the `Remote Folder`. The `Sync Folder with Remote` dialog uses the same layout now. See the [SFTP plugin](../plugins/sftp.md#sync-files-with-remote) page.
- **SFTP**: the remote folder and file browser dialog now supports type-ahead search. Type the first letters of a name to jump to the matching entry (typing again within about a second continues the search). `Backspace` still goes to the parent folder.
- **SFTP**: the `Sync Folder with Remote` dialog and the remote browser dialog now use the alternate row colours, and the sync dialog opens at a size that fits its content.
- **Language Server**: the `Language Server` view now has two tabs, `Progress` and `Log`. The `Progress` tab shows the progress that language servers report (for example, indexing). Each task has its own row with the server name, a progress bar and a message, and the row is removed when the task is done. The progress updates are no longer written to the log.
- **File System Workspace**: added a `Sync File On Save` option to the `Remote` page. When it is enabled, every file you save or change with Replace in Files is also uploaded to the remote machine, and renamed or deleted files are renamed or deleted there too (folders are not synced). The option is off by default, so enable it in existing workspaces that use remote development. See the [File System Workspace](../workspaces/file_system.md#remote) page.
- **File System Workspace**: renaming a file in the workspace tree now lets source control plugins (for example Subversion) do the rename.
- **Tab Groups** are removed: the `Groups` tab of the side bar, the `Load a group of tabs` and `Save tabs as group` items of the `File` menu, and the documentation page. Existing `.tabgroup` files are not deleted.
- **Chat AI** is removed, with everything that used it: the `Chat AI` menu (chat window, prompt editor, system prompt, endpoints, MCP servers), the `AI Options` and `AI-Powered Options` context menus, the AI commit message button of the Git commit dialog, the Git release notes generation, and the Lua functions `codelite.chat()` and `codelite.generate()`. There are many good AI agents out there: use **Agent Host** to run one inside CodeLite. A Lua script that calls the removed functions fails when the function is called, so remove those calls from your `codelite.lua` script (the default script no longer has them). The settings that Chat AI saved (`assistant-global-settings.json` and the chat history) are not deleted.
- **Agent Host** no longer passes a system prompt to the agents. Files that older versions wrote are not deleted: `SYSTEM_PROMPT.md` and `opencode.json` in the CodeLite settings folder and in the `.codelite` folder of the workspace, and `.kiro/steering/SYSTEM_PROMPT.md` in the workspace. Kiro CLI still reads the last one, delete it if you don't want it.
- **AgentHost**: the tab of an agent shows the spinner also while its Review Buddy is working.
- The **Output** pane no longer has the drop-down button and the `Hidden Tabs` menu. The tabs share the available width, and the scroll buttons appear when they do not fit.
- **Agent Host**: after you click a file link in the terminal, the file opens and the editor gets the focus.
- CodeLite now comes with the **Iosevka** font (Iosevka, Iosevka Fixed and Iosevka Term, licensed under the SIL Open Font License). **Iosevka Term** is the new default editor font, so you do not need to install a font yourself (on Linux, the default is **Iosevka**, because Pango does not find the `Iosevka Term` face of a font that is loaded at run time). Your own font choice is not changed.
- When you start CodeLite with a workspace on the command line, CodeLite opens that workspace and does not restore the last session.
- **Markdown files** now open in a page with a toolbar, with two buttons. `View` shows the rendered document and `Edit` shows the editor with the text of the file. The button that you click is remembered: the next Markdown file opens in the same mode (`View` is the default). Save, Save All, the modified mark of the tab, the session and the plugins work as for any other file.
    - The view shows headings, emphasis, strikethrough, lists (also task lists), quotes, links, tables, horizontal rules, code and local images. Inline code has its own colour, and a code block has a background that covers the whole width, with a border. Images that need the network and raw HTML are not shown as pictures (raw HTML is shown as text).
    - The colours fit the editor: headings use the colour of a class, bullets use the colour of a number, and borders follow the background of the C++ lexer of your theme. The text has the font size of the editor.
    - The view is made from the text in the editor, so it also shows changes that are not saved yet. Click a link to open it: web addresses open in the browser, a path opens the file or folder (relative to the Markdown file), and a link to a heading (`[text](#some-heading)`, for example in a table of contents) scrolls to that heading. The address of a link is shown in a tooltip when the mouse is over it.
    - Opening a file at a given line (for example from the `Find In Files` results) shows the editor. Text commands (`Find`, `Zoom In`/`Zoom Out`, delete line, comment, go to line, ...) also switch to the editor, and then act on it. `Copy` and `Select All` in the view work on the document. The view follows the zoom of the editor, but it has no zoom of its own.
    - Markdown files that are opened from a remote (SFTP) account still open in the editor only.
- **Agent Host**: added a toolbar with the buttons `Restart`, `Run Review Buddy` (a drop-down to pick the agent of the review), `Copy`, `Paste`, `Find In Files` and `Open Resource`. The terminal has no right-click menu anymore, its actions are in the toolbar. `Find In Files` and `Open Resource` open their dialogs with the selected text, and are disabled when nothing is selected. When the agent handles the mouse itself (for example inside `tmux`), the text it copied with the `OSC 52` sequence is used. See the [Agent Host](../AI/agent_host.md#toolbar) page.
- On Linux, the default editor font size is now 18 (it was 14), because the old size was too small with the new default font.
- The right-click menus of the editor and of the editor tabs now show the correct keyboard shortcuts.
- **Agent Host**: added **Review Buddy**. A second agent (any of the supported agents) reviews the work that is not pushed yet, in a pane next to the main agent. Start it from the `Run Review Buddy` button of the Agent Host toolbar.
    - The two agents work in the same folder and talk to each other through files in `.agents/reviews/<id>/`. The reviewer writes its comments, the main agent fixes them, and the reviewer checks again. This repeats until the review is clean, or for at most 5 rounds.
    - CodeLite types the requests into the terminals for you and tells you when the review is finished, when the round limit is reached (the last fixes are not reviewed in that case), or when an agent seems to wait for you for a long time. If you are not looking at the page, you get a system notification.
    - While a review exists, the `Run Review Buddy` button opens a menu with `Resend`, `Stop`, `Open the Latest Review` and `Close Review Buddy`.
    - It needs a working directory inside a git repository (a sub-folder or a worktree is fine). It works for remote workspaces too. The `.agents/reviews/` folder is added to `.git/info/exclude`, so it does not show in `git status`.
- **Agent Host**: the sash between the terminals now has a 3D look.
- The `View` menu now has `Open Terminal...`.
- **PHP**: XDebug now works with any local workspace that has `XDebug` selected as its debugger. The settings are in the new `PHP` → `XDebug Settings...` dialog, and are stored in `.codelite/xdebug.json`. See the [XDebug](../debuggers/xdebug.md) page.
- **PHP**: the XDebug setup wizard now writes Xdebug 3 settings (`xdebug.mode`, `xdebug.client_host`, `xdebug.client_port`, `xdebug.start_with_request`), and the default port is now 9003. Saved settings keep their port. Command line debugging now uses `XDEBUG_SESSION` and `client_host`/`client_port`.
- **wxCrafter**: the folder for the generated base classes is now selected with `WXCGEN_FOLDER_MAP=<base_dir>=<target_folder>`. Set it as an environment variable, or in a `.wxcrafter-environment` file (one `NAME=VALUE` per line) in the `.wxcp` folder or in one of its parent folders. This replaces the `.wxcgen.json` file, and `wxcgen` no longer has the `-p` option. The wxCrafter UI and `wxcgen` use the same rule.
- **wxCrafter**: new option `Generate the bitmaps code inside the base class source file` in the wxCrafter settings. It is off by default: the bitmaps code is still written to the separate `*_bitmaps.cpp` file, so existing build systems keep working. When it is enabled, no `*_bitmaps.cpp` file is generated.
- **wxcgen**: new switch `--bitmaps-in-base-class-file` (the same as the option above), and new switch `--verbose`, which prints the output folders and the generated files of each input file.
- **wxcgen**: new switches `--install-skill-local` and `--install-skill-global`. They install an AI skill (`.claude/skills/wxcrafter`, under the current directory or the home directory) that teaches an AI coding agent how to create and edit `.wxcp` files, with a reference of the `.wxcp` format and of every control. See the [wxCrafter, wxcgen & AI skill](../plugins/wxcgen.md) page.
- The `Plugins` dialog (plugin manager) now uses a list with check boxes, and supports type-ahead search.
- The layout of the `Environment Variables` dialog, the `Keyboard Shortcuts` dialog and the `New Keyboard Shortcut` dialog was improved. The text in the `Environment Variables` dialog is wrapped.
- **Language Server**: added support for doc blocks generated by the language server. Type `/**` above a function or class and press `Enter`. See the [Language Server](../plugins/lsp.md#docblocks) page.
- **Language Server**: added support for document links, for example the file of an `#include` or `require` statement. `Ctrl`-click a link to open it. See the [Language Server](../plugins/lsp.md#document-links) page.
- The shortcuts of the main frame (for example `F6`, which toggles the terminal view) now work while a built-in terminal has the focus, including the Agent Host terminals.
- The `Find In Files` and `Replace In Files` views now show a status line at the top with the search description and summary. They are no longer written into the results text. The views use a themed toolbar, and the width of the horizontal scrollbar is calculated once, when the search ends.
- The `Find In Files` dialog and the `Replace In Files` panel now use a better font size on Windows.
- The recent workspaces on the welcome page are now shown in a list with the columns `Name`, `Account`, `Type` and `Path`. Click a column header to sort, and type to search. Local workspaces use a house symbol and remote workspaces use a globe symbol.
- The built-in terminal now starts in the working directory it is given, and uses `bash` (MSYS) as its shell on Windows.
- **Git**: the `Git` view now refreshes when a file that is open in CodeLite is changed or deleted outside of the editor (for example by an AI agent). When many files change, the view is refreshed only once, after the changes stop, and not at all if it was already refreshed in the meantime. This also works in remote workspaces.
- **PHP**: PHP support now uses the PHP language server ([`phpantom_lsp`](https://github.com/PHPantom-dev/phpantom_lsp)) and a [File System Workspace](../workspaces/file_system.md). See the [PHP](../workspaces/php.md) page.
    - PHP workspaces and projects are removed, with their UI: the new project wizard, the new class dialog, the project settings, `Open Resource`, the quick outline, `Generate Setters / Getters`, the PHP editor context menu and the SFTP sync of PHP workspaces.
    - An old PHP workspace is converted to a File System Workspace when you open it. The old file is kept as `<name>.workspace.php-backup`, the XDebug settings and the breakpoints are moved to `.codelite/xdebug.json`, and the SFTP settings become the remote target of the workspace.
    - The built-in PHP parser, its code completion and the PHP stubs zip file are removed. Code completion and navigation now come from `phpantom_lsp`.
    - The **PHPRefactoring** plugin is replaced by LSP code actions (`Alt-Enter`), including actions that create or rename files.
    - The **PHPLint** plugin is replaced by the LSP diagnostics.
    - The button to test the XDebug settings is gone.
    - Removed the `Use system default browser` option of the XDebug settings (web sites always open in the default browser) and the `error_reporting` field of the PHP settings (the value was never passed to PHP).
- **Terminal**: the built-in terminal and the Agent Host terminals use the new terminal emulator, with a progress bar above the terminal (for programs that report progress with the `OSC 9;4` sequence), a hollow cursor when the terminal does not have the focus, better performance with large output, and correct mouse handling inside `tmux`. Text that a program copies with `OSC 52` goes to the clipboard of the terminal that has the focus.
    - The tab of a terminal shows what its program does: a spinner while it works, a pulse while it waits for you, and a check mark when it is done. The last two are shown only when the tab is not selected, and are removed when you select it. The tab of an agent uses the same icons.
    - The terminal settings have two new options, `Show Progress Bar` and `Notify When Done`, and a colour for the outline of the current tab (with a preview).
    - The tabs are drawn with the colours of the terminal theme.
    - The CodeLite folder (where `wxcgen` and the other tools are) is added to the `PATH` of the built-in terminal.
    - `Ctrl-N` (new file), `Ctrl-Shift-F12` and the other shortcuts of the main window also work while a terminal has the focus. `Ctrl-M` is no longer taken by the terminal, so a shell receives it as `Enter`. When the pane gets the focus, the focus goes to the terminal of the selected tab.
    - On Windows, `conpty.dll` and `OpenConsole.exe` are installed next to `codelite.exe`.
    - On Linux, the OpenGL terminal is optional: build with `./build.sh --opengl`. With OpenGL, CodeLite runs on X11 with a client side title bar (set `GDK_BACKEND` or `GTK_CSD` to change that).
- **Agent Host**: when the main agent is blocked, done or failed and you are not looking at its tab, the tab shows an icon (a pulse for blocked, a check mark for done), and CodeLite flashes the taskbar button or bounces the Dock icon, only when the agent is blocked and CodeLite is in the background. Nothing is shown while a review runs, and `Notify When Done` turns it off. When the agent is done, the `Git` view is refreshed. The colours of the agent follow the theme of the terminal, and the Claude Code terminal bell is passed to CodeLite.
- **Agent Host**: **Review Buddy** has a finish message with the buttons `Ok` and `Ok & Close Review Buddy` (the last answer is remembered). The `Settings` dialog has a `Review Buddy` page with extra command line arguments for the Claude Code and Kiro CLI reviewers (for example, a custom agent).
- **Find Usage**: the `Find Usage` view (find references) has a new layout. The files are on the left, and the matches of the selected file are on the right (`Line` and `Match`, with syntax highlighting). The sash is remembered. The files are shown with the line number (`file:line`), and a filter field above the list matches the file name or the text (not case sensitive, start a word with `-` to exclude it). The `Hide Results From Build Folders` toggle (on by default) hides results from folders whose name starts with `.build`.
- The **Diff** view now opens in a tab of the main notebook, and not in a separate window. The tab shows the name of the file, and you can have several diffs open. If the same diff is already open, its tab is selected. The file pickers are hidden when the diff is started from source control.
- **Tab switcher** (`Ctrl-Tab`): the popup is lighter, so the switch is no longer delayed, and it has rounded corners. It shows the icon of tabs that are not files (for example a diff). Fixed `Ctrl-Tab` and `Escape` not working in it on Windows and macOS.
- The code completion box and its tip now have rounded corners and a shadow, like the tab switcher (on macOS, a translucent blurred background). The hover box has a better look, and highlights code snippets.
- `Toggle Minimal View` (`Ctrl-M`) now remembers which panes (the left side bar, the right side bar and the Output pane) were visible, and hides them all. Toggling again shows the panes it hid, or all of them if none were hidden. `Toggle All Panes` is removed, and double-clicking an editor tab toggles the main panes like the minimal view.
- **Language Server**: `Code actions...` (`Alt-Enter`, or from the right-click menu) now offer refactorings and the quick fixes of the server, including actions that create or rename files. See the [Language Server](../plugins/lsp.md#code-actions) page.
- **Language Server**: the language server can format the code, also the selected lines only. This replaces the PHP formatters of the PHP plugin (`PHP-cs-fixer` and `PHPBCF`), which used their own settings.
- **Markdown files**: a toolbar button shows or hides a table of contents (one row for each heading) at the right of the document. Click a row to scroll to the heading. The choice is remembered, and the table is hidden by default. The right-click menu has `Copy` and `Select All`, and the mouse wheel scrolls three lines per step.
- **Git**: the actions of the Git plugin are registered in the `Keyboard Shortcuts` dialog, so you can assign shortcuts to them ([#4187](https://github.com/eranif/codelite/issues/4187)).
- Starting `Find In Files` or `Replace In Files` shows the Output pane with the `Search` or the `Replace` view.
- The `Add function implementation` dialog now uses a native list control.
- **wxCrafter**: all the icons are now SVG images, in a version for dark themes and a version for light themes, so they stay sharp on high DPI screens. The tool box is no longer generated, and its pages use the tab design of CodeLite.
- **wxCrafter**: new form type `wxPopupTransientWindow` (the generated class has the `Popup()`, `OnDismiss()`, `ProcessLeftDown()` and `Show()` methods that a subclass can override), and support for the `wxEVT_CHILD_FOCUS` event.
- **wxCrafter**: the positions of the splitters and the size of the window are remembered. The standalone Windows installer registers the `.wxcp` file type.
- **SFTP**: the checksum of a remote file is calculated in the worker thread.
- CodeLite has a new command line option, `--loglevel` (`-L`), which sets the log level (`error`, `warning`, `info`, ...). See the [build](../build/build_from_sources.md) page.

## Build

- `build.sh` now builds wxWidgets `v3.3.4` on macOS and Windows, and `v3.3.2` on Linux. wxGTK `v3.3.3` and newer crash the WSLg Weston compositor when copying text with `Ctrl-C`.
- Installed binaries no longer contain the build directory in their `RPATH`. They only look in the plugins directory. This is needed by strict packaging systems such as OBS ([#4079](https://github.com/eranif/codelite/issues/4079)).
- `build.sh` has two new Windows-only targets: `wxcrafter` builds wxCrafter, and `package_wxcrafter` also creates the installer.
- `build.sh` has a new option, `--no-build`. It runs cmake only and skips the build step.
- Windows: building CodeLite no longer needs `wx-config-msys2`. CMake finds the wxWidgets that `build.sh` builds using its CMake package config, and `build.sh` no longer builds `wx-config-msys2`.
- The `wxcrafter_target` CMake macro no longer takes an output folder: the base classes are generated in the build folder, in the same relative path as the `.wxcp` file has in the source folder. It passes `--bitmaps-in-base-class-file` to `wxcgen`, so the `*_bitmaps.cpp` file argument is gone too. If you use the macro in your own CMake files, remove these arguments.
- Plugin API: the `wxEVT_CMD_OPEN_RESOURCE` event (a `wxCommandEvent`) was replaced by `wxEVT_OPEN_RESOURCE_SHOWING`, which carries a `clOpenResourceEvent`. If your plugin handles it, change the event name and the type of the handler argument. `clFindInFilesEvent` also has new `Get/SetFindWhat()` and `Get/SetReplaceWith()` methods, and a plugin can use them in its `wxEVT_FINDINFILES_DLG_SHOWING` handler to fill the `Find In Files` dialog.
- [md4c](https://github.com/mity/md4c) (a Markdown parser) is a git submodule: `submodules/md4c`. Run `git submodule update --init --recursive` after you pull. It is linked into `libcodelite`, and it is used by the new `clMarkdownParser` class (`CodeLite/`) and by `clRichTextMarkdownRenderer` (`Plugin/`).
- `build.sh` has a new Linux option, `--opengl`, that builds wxWidgets and the terminal with OpenGL support (it needs `libgl-dev` and `libglew-dev`). The wxWidgets patches of the `wxTerminalEmulator` submodule are applied on every platform, and `build.sh` prints why a patch is skipped. On Windows, `CL_WX_VERSION` selects the wxWidgets version. The script also reports its progress, status and the build stage to the terminal tab.
